# tray-info

Windows tray app (Rust, plain Win32 via the `windows` crate) that shows numeric icons for:

- battery level of every connected Bluetooth device that reports one;
- CPU temperature;
- CPU package power.

Priorities: it must work reliably and stay cheap — no async runtime, no GUI framework, no
background threads of our own. One UI thread, a hidden window, two coalescable timers.

## Commands

```powershell
cargo fmt
cargo clippy --all-targets      # must report zero warnings
cargo test
cargo build --release           # target\release\tray-info.exe
.\install.ps1                   # author's machine only: build, copy to C:\Bin, restart
```

Running a second copy is a no-op (single-instance mutex). To restart after a rebuild, stop the
running `tray-info.exe` first. Diagnostics go to `OutputDebugString` (view with DebugView).

## Layout

- `src/run.rs` — process entry: single instance, DPI awareness, COM, hidden window, window
  procedure, timers, message loop, menu command handling.
- `src/app.rs` — `App`: sensors, latest readings, which tray icons to show, menu contents.
- `src/sensors/` — data sources and domain types (`BatteryLevel`, `BluetoothAddress`,
  `Celsius`, `Watts`, `TemperatureReading`, …).
- `src/render/` — icon look: `palette.rs` maps readings to an `IconSpec` — `Ring` (Segoe Fluent
  Icons device symbol inside a level ring, for batteries) or `Reading` (small symbol top-left,
  large Segoe UI Light digits bottom-right, for CPU readings); `icon_painter.rs` rasterises
  a spec into an `HICON` on a `Canvas` (anti-aliased ring, GDI text masks → alpha). GDI picks
  font weight by the named instance in the family name ("Segoe UI Light"), not by `lfWeight`.
- `src/tray/` — `Shell_NotifyIcon` wrappers, stable icon ids, popup menu (actions only; readings
  live in the tooltips).
- `src/win/` — thin safe wrappers: configuration manager (`DevNode`), PDH counters, WMI method
  calls, autostart (Task Scheduler logon task with highest privileges), single instance mutex,
  elevation relaunch, debug log.
- `src/autostart_request.rs` — `--set-autostart on|off <user>`: registering an elevated task
  needs admin rights, so the unelevated app starts an elevated copy of itself with this request;
  that copy changes the task and exits.
- `assets/tray-info.ico` — executable icon, generated by `src/render/app_icon.rs` with the tray
  painter (`cargo test --lib regenerate_app_icon -- --ignored`); `build.rs` turns it into a
  `.res` the MSVC linker embeds (no `rc.exe` needed).

## Data sources (and why)

| Metric | Source | Rights |
|---|---|---|
| BT battery | `DEVPKEY_Bluetooth_Battery` `{104EA319-6EE2-4701-BD47-8DDBF425BBE5} 2` on `BTHLE\DEV_*` nodes (BLE) and on `BTHENUM\{profile}_…_<addr>_C00000000` nodes (classic HFP headsets); connected flag `{83DA6326-97A6-4088-9453-A1923F573B29} 15`; name `DEVPKEY_Device_FriendlyName`; device type `DEVPKEY_DeviceContainer_Category` (`Input.Mouse`, `Communication.Headset.Bluetooth`, …) on the device node | user |
| CPU power | PDH `\Energy Meter(*)\Power`, instance `RAPL_Package<N>_PKG`, milliwatts (EMI driver) | user |
| CPU temp | `root\WMI` `LENOVO_OTHER_METHOD.GetFeatureValue(IDs=0x05040000)` → `value` (Lenovo Legion EC, 2022+ models); fallback `LENOVO_GAMEZONE_DATA.GetCPUTemp` → `Data` for older models (newer ones answer 0 there) | admin |

Windows has no unprivileged, generic CPU temperature API: ACPI thermal zones are often missing
and MSR access needs a kernel driver. Other vendors/machines need their own `CpuTemperatureSensor`
variant. Reading BT battery never opens GATT connections, so it does not drain device batteries.

When running elevated, `ChangeWindowMessageFilterEx` must allow the tray callback message and
`TaskbarCreated`, otherwise UIPI drops Explorer's messages.

## Engineering rules

Copied from the Globo `globo-dev` and `globo-dev-rust` standards that apply to this repository.

### General

- Write short comments that explain the reason for a decision and non-obvious algorithms; do not
  narrate obvious code.
- Always comment an action that looks redundant but is needed for synchronisation, atomicity,
  lock ordering or race protection.
- When wrapping errors keep the original cause. At boundaries where only a string is available,
  include the full cause chain (`{error:#}`) so the lowest-level message stays visible.
- No tuples with more than two elements; introduce a named type.
- Use a boolean flag (parameter, field, test parameter) only when its name makes both `true` and
  `false` obvious: `true` enables the named action/attribute, `false` disables it. If `false`
  means a different variant rather than absence, use an enum with named variants.
- Add tests for new functionality.
- Test observable behaviour and results, not the shape of the implementation. Do not assert on
  literal configuration strings and do not require one internal function to call another.
- When fixing a bug, add a test that reproduces the defect through the real code path.
- Do not delete meaningful tests without explicit permission.
- Parameterise a test only with variants of one scenario (same actions and checks, data
  substituted). Never branch the test body on a parameter; write separate, well-named tests and
  extract shared setup into a helper.
- Update existing documentation (this file, README) after adding functionality or materially
  changing behaviour or configuration.
- Do not duplicate code; extract shared logic into a common module.
- Prefer domain value types over primitives when they add meaning; use primitives at boundaries
  or when a wrapper adds nothing.
- Convert unvalidated input into a validated type; expose operations that rely on its invariants
  only through that type.
- Get explicit permission before an incompatible change of a public API; prefer compile-time
  incompatibility over run-time incompatibility.
- No sleeps or polling in tests; prefer event-based synchronisation, controlled clocks or test
  infrastructure signals. Do not test internal timeouts by waiting in real time.

### Rust

- Keep `mod.rs` limited to module declarations and re-exports; implementation lives in separate
  files.
- Prefer at most one type (`struct`, `enum` or `trait`) per file. Grouping related functions is
  fine.
- Never silently ignore a `Result` with `let _ =`. Propagate with `?` or handle explicitly
  (`expect`, `unwrap_or`, `if let Err`, logging via `debug_log`).
- Run `cargo fmt` before finishing a change and include its formatting edits.
- Run `cargo clippy` and leave exactly zero warnings.
- Treat `.clone()`, `.to_string()` and `.to_owned()` as smells that need a reason. Prefer `&str`
  / `&'static str` for low-cardinality names, `Arc<str>` for shared strings, and borrowing APIs
  unless ownership is inherent.
